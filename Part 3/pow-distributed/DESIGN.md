# Dashboard design

An operating interface for a local distributed systems demonstration. Use a
light, warm background for classroom screens, dark slate text, restrained green
actions, and separate blue/running, green/found, amber/cancelled and red/error
states. Color always accompanies a text label.

The submission form and selected job share the first desktop row. On mobile,
stack them before workers and history. Workers use compact cards; history uses
a horizontally scrollable table. Hashes wrap fully; identifiers use monospace.
Native system typography keeps the dashboard offline and dependency free.
Use visible keyboard focus, associated labels, semantic headings, polite status
announcements, disabled pending actions and reduced-motion support. Only the
initial heading has a brief opacity/translation entrance; measurements render
directly from backend snapshots without interpolated counters or percentages.
